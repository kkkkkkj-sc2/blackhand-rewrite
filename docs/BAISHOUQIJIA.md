## 数据及实现

- 原始导出、显式席位覆盖、物理能力位、权重及确认项：[baishouqijia.json](<../work/presets/baishouqijia.json>)。这是保存码解码记录，不是旧 [preset_gen.py](<../tools/preset_gen.py>) 的随机预设 schema；不要对它运行旧生成器。
- 生产实现：[CustomLogic.galaxy](<../work/blackhand/CustomLogic.galaxy>) 中 `gf_VBSQJOptions`，数据变动须同步 JSON 并运行专项测试。
- 文案：[strings-bsqj.txt](<../work/blackhand/strings-bsqj.txt>)。介绍保持用户原句，不擅改「初来咋到」。
- 回归入口：`python3 tools/test_baishouqijia.py`；仅验证规格与历史溯源用 `--spec-only`。测试先逐字校验并解码原码，再叠加唯一的席位覆盖，证明其余 14 席不变；生产静态检查另沿名称链验证 4/14。未同步生产席位串时，完整回归应失败，而不是放宽预期。C++ 快照、污染及逐项比对循环覆盖到实际 `c_bhSaveRoleMax`，包括裁决者（3/38）；旧码缺失的裁决者权重仍只取当前初始化默认，不在白手起家另设覆盖。测试明确要求精神病患者（3/25）与裁决者（3/38）的初始/缺项恢复权重均为 0.25，污染后重选仍恢复；并检查初始快照调用晚于裁决者完整注册，避免捕获尚未初始化的 0。

旧 `-save` 不是完整银行快照：角色仅打包物理位 0–4，未导出中立 19–37、所有高位开关与三项特殊规则，尾部 flush 也有遗留缺陷。中间双空格来自随机池没有权重，不应误判为缺失中立权重。本实现不依赖 `StringWord` 是否保留空字段，也不调用有误解码的 `gf_OSLoadBase64`。

按导出端含义恢复全局设置：白天开始、首日不能处决、白天类型 2；遗嘱、晨间讨论、夜间演出、死因描述、私信、审判辩护、审判暂停白天、自设名字全部开启。银行 Trial 为 `1211001111000`。时长使用当前加载器实际允许的 1.2 / 0.6 / 0.3 / 0.8；原码白天解出 1.1，低于加载器最小值 1.2。

物理位按当前 `Exists` 压紧成银行能力词；没有开关也写 `0`，确保该角色的权重会经 `gf_VLoadSaveSlot` 同步。新增中立的缺失权重不会被板子共用权重表覆盖。

`gf_DefaultRoleOptions` 没有重写所有新增中立的默认项，所以不能拿它每次更新的快照或 bank0 作为稳定初值。本预设另在 `gf_InitializeVariables` 完成后调用一次 `gf_BSQJSnapshotDefaults`，保存初始能力及 bank0 权重；每次载入白手起家都从这个隔离快照补缺，避免继承先前板子的设置。不改变其他预设的通用重置逻辑。

## 单人验证包

工作区的 `c_bhSoloBuild` / `c_bhSoloFill` 继续保持 false，常规测试补位上限仍为 6。仅测试此预设时，从源码临时副本将 `c_bhSoloFillMax` 改为 15，再用 `boot2_build.py --galaxy <临时副本> --solo` 出包；不要修改工作区的发布开关。单人验证包必须回读确认两开关 true、补位 15、自定义三件为纯本地依赖；普通包须确认两开关 false、补位仍为 6、自定义三件为纯战网依赖。
