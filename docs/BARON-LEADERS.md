# 男爵 / 泰斗（shw308）

## 行为与入口

- 男爵为黑手党领袖 `2/22`，泰斗为三合会领袖 `5/22`；每晚一刀，固有夜间无敌，可被限制和关押。
- 开局在随机槽解算后、优选预占和职业 setup 前，保留领袖，将**己方**其他帮派席替换为随机城镇并真实归城镇；不改变另一帮派。使用有名称、正权重的城镇职业，空权重池回落市民。
- 仅全局第一夜可招募，男爵和泰斗各自通过互斥开关选择至多二／三／四人，默认三人；出刀和招募名单互相独立。按钮可逐人选择/取消；`-recruit 1 2 3`（四人档可加第四个楼层）按**楼层**原子替换整份名单，无参数清空。重复、无效、自选或超过本角色人数上限的参数不会部分修改原名单。
- 选择时只检验公开的存活和楼层条件，不反馈隐藏阵营。中立或帮派目标可以留在待定名单，但结算不合格就落空，避免无限指令探测阵营。
- 首晨在关押/限制清零前冻结领袖行动资格；在急救复活完成后、首次判胜前，使用原阵营转换入口，只招募最终存活、非假死且真实属于城镇的目标。男爵招入黑手党，泰斗招入三合会。
- 领袖第一夜死亡则不招募。shw315 在冻结与最终提交两处同时检查存活组和 `gv_diedAtNight`，防止死亡已标记但晨间尚未从存活组移除的窗口仍然取得资格；冻结失败后，清理夜死标记也不会恢复其资格。该限制只检查领袖，不改变首晨急救复活后目标的合法招募。
- 招募当时保留职业、次数、冷却等能力状态，不立即获得帮派刀；本人收到原有私密入帮提示，无额外公屏转换播报。若之后己方缺少可以杀人的角色，在原有入夜继任时机成为党徒 `2/1` / 暴徒 `5/1`（详见下节），并清除旧阵营覆盖。
- 招募不产生访问；出刀接管既有帮派 hitman/target，继续标准单刀链，沿用交换、限制、救治和保镖处理。
- 疯子模仿22时具有相同的假招募按钮/指令反馈，但不能获得真实夜间无敌、帮派刀或招募转换资格。

## 招募成员的继任

- [主脚本](<work/blackhand/CustomLogic.galaxy>) 的 `gf_RSConversions` 在每次入夜、行动面板与职业准备之前统一处理；首晨招募仍只转换阵营，男爵/泰斗死亡后也不在死亡回调里即时改职。
- 招募成员通过实际阵营计入存活帮派人数，与原生普通角色在同一玩家编号循环竞争一个刀口；继任成功立即增加该阵营刀口计数，其他招募成员保留原职业，下一次缺刀时才再继任。原生领袖、参谋/管家保留原开关与优先级，弃子/死士仍最后垫底。
- `gf_BHConvertedSuccession` 只使用原规则的 `alive` 成员资格、刀口计数和参谋/管家升领袖保留门。原继任没有额外 `feign`、限制或关押字段门，此处也不新增；真正假死者已从存活组移除，不参加继任。首夜招募自身的非假死及限制/关押资格检查不变。
- 真正继任时将职业写为相应阵营 `1` 号并清零 `gv_bhFaction`，把旧城镇的永久基础票权归一、次数盾和两个旧行动目标清零，再按原流程刷新角色卡、统计及私密继任提示；这些只在继任改职时清理，首晨入帮仍保留全部职业能力及已选目标。清旧目标可避免原狱警白天关押选择被当作当夜帮派杀人目标。不重跑旧城镇职业 setup，不重置开局职业、次数、冷却或访问。
- [继任专项](<tools/test_baron_succession.py>) 执行真实完整继任分发及所有被调用角色函数；[律师继任回归](<tools/test_lawyer_conversions.py>) 保留原生规则检查。均不是 SC2 引擎完整对局实测。

## 行动显示与配色（shw312）

- 两名领袖的招募按钮 hover 只显示“招募”；选定击杀目标后隐藏该目标的“杀死”按钮，自己一栏显示“取消”（hover 也为取消）。改选其他目标后恢复旧目标按钮；取消出刀不清招募名单。
- 首夜仅提示“你的首要目标是扩充自己的势力。今晚你会尝试招募一些城镇角色加入黑手党。”；泰斗对应“三合会”。不再自动附加长指令说明，输入有误时提示无效目标或当前人数上限。
- 两张卡的类型均为“致命，领袖”。男爵名称、类型标签和行动按钮使用柔和玫红 `C96B78`；原职业加入黑手党后的身份名称及入帮提示使用暖杏橙 `D9A08F`。
- 泰斗名称、类型标签及按钮使用柔紫 `A292CC`；原职业加入三合会后的身份名称及入帮提示使用雾蓝 `8FBFD1`。与领袖分开配色，不改变调查的职业语义或阵营判定。
- 成功招募时本人分别收到“你转变为「黑手党／三合会」阵营。”的私密提示，不向其他人广播。真实首晨转换及消息收件者有回归检查。
- [配色回归](<tools/test_baron_colors.py>) 校验文案色值、Galaxy 百分比颜色与显示入口一致。黑底对比度数值不是实际引擎渲染验证。

## 招募人数开关（shw313）

- 两角色分别登记 `0=可以招募二人`、`1=可以招募三人`、`2=可以招募四人`，仅三人默认开启。点击采用单选，全部关闭自动回三人；旧档异常多开在最终配置应用时按四＞二＞三归一，不改存档格式。
- `gf_BRRecruitLimit` 为名单、按钮、命令、结算及角色卡提供同一个人数上限。两帮派配置相互独立；疯子模仿按对应呈现的帮派开关显示反馈，但依然没有真实招募权限。
- 招募数组扩为 `int[16][4]`；重开、无参清空和首晨收尾均清四格。命令先校验全部参数，再替换整份名单；超限不截断也不部分覆盖。结算只处理实际启用人数范围，防止残留高位槽绕过上限。
- 角色卡显示本局实际人数上限；名单显示 `已选数/上限`，按钮及命令超限均报告该角色的实际上限，文案不再写死三人。
- [选项回归](<tools/test_baron_options.py>) 执行真实默认表、规范化和完整选项点击处理器，96,199项检查；[招募业务回归](<tools/test_baron_leaders.py>) 执行真实按钮／指令／首晨结算，161组场景、60,652项检查，包含两角色三档、四名实际转换、双领袖不同人数、旧名单残留清理和疯子无权真实招募；均通过 UBSan/bounds。
