# 陷阱师与天工

## 角色与行为

| 项目 | 陷阱师 | 天工 |
|---|---|---|
| 角色号 | 2/20 | 5/20 |
| 拼音 | xianjingshi | tiangong |
| 阵营 | 黑手党 | 三合会 |
| 分类 | 支援、致命 | 支援、致命 |
| 名称色 | C66B4E | 5A83C6（蓝） |
| 陷阱不攻击 | 黑手党 | 三合会 |
| 访客优先级 | 城镇 > 三合会 > 中立 | 城镇 > 黑手党 > 中立 |

- 每晚可选一个房屋布置陷阱；全局最多成功布置两次，不自动制作或补充。
- 首夜禁止布置。成功布置在第 N 晚，N+1 晚休整，N+2 晚才能再次布置。
- 例如第 2 晚布置，第 3 晚休整，第 4 晚可布置第二次。限制、关押等导致布置失败不扣次数、不产生休整。
- 陷阱沿用护林人：含布置当夜最多存在两晚；一旦选定可攻击访客，即耗掉该陷阱，哪怕访客被治疗或保镖拦截。
- 夜间无敌访客不列入攻击候选；只有无敌或本阵营访客时不消耗触发，陷阱仍按夜晚自然到期。优先级相同者随机选一人。
- 第一、第二访问槽都视为访问。房主和布置者自身不是陷阱候选。
- 布置不受巴士司机影响，女巫仍可改变实际访问目标；调查读取实际访问。
- 既有陷阱不依赖布置者当夜是否存活、被限制、关押或处于休整期。阵营按布置时快照，不随布置者后续转化改变。
- 沿用护林人的治疗、保镖、免疫、击杀演出和死因 T；黑手党/三合会陷阱也不会误伤本阵营的拦截者。
- 新角色默认随机权重为 0，可在自设直接添加；调高权重后可进入全体、本阵营、支援、致命随机，不属于领袖随机。

## 代码接线

- `gf_HLGangSetup`：初始化两次布置额度，显示正常、首夜、休整或耗尽的面板。
- `gf_HLGangPick`：面板选择守卫，复用原护林人目标确认。参数名遵守 `sk_verify` 的同名实参约束。
- `gf_SequencePrep`：复用护林人巴士免疫入口，并写入新角色实际访问。
- `gf_HLForesterNight`：三种角色共享布置与既有陷阱结算；只有新角色写 `gv_hlNextNight`。
- `gf_HLResolveOne` / `gf_HLTier`：按布置时阵营筛选与排序，城镇护林人规则不变。
- `gv_hlFaction[16][2]`：每个陷阱的阵营快照；`gv_hlNextNight[16]`：下次允许布置的夜晚编号；`gv_hlGangInitialized[16]`：防止每晚面板刷新补满次数。
- `gv_mafiaTriadMax` 放宽到 20，以覆盖权重与保存格。普通累计权重在 `gf_OSRandomize`、`gf_OSGenerateChances` 两处跳过 17–19，保持原先仅由领袖随机选出的行为；20 号有独立权重区间与映射。
- 两池审查页上界 18，对应角色 20；自设列表由 `work/roles-list.json` 生成，两处菜单映射同步。
- 角色卡只写各自池的函数；镜头、警长、胜利与首胜沿用现有阵营通路。探员静态候选列表补入两个新角色。

## 验证

```bash
python3 tools/test_trap_roles.py
python3 tools/galaxy_lint.py
python3 tools/role_gen.py
python3 tools/role_card_check.py --strict
python3 tools/role_list_gen.py --check
python3 tools/strings_check.py
python3 tools/boot2_build.py --out work/boot2-traps-check.SC2Map
python3 tools/boot2_build.py --out work/boot2-traps-solo.SC2Map --solo
```

`test_trap_roles.py` 抽取实际 Galaxy 函数体，用 C++ 引擎桩执行并启用越界/未定义行为检查。覆盖两阵营、首夜、两次上限、休整、选目标、双访问槽、敌我优先级、平级随机、治疗、无敌、保镖、布置者失能、转换快照、普通随机累计及映射。可附 `--baseline <修改前脚本>`，对城镇护林人执行 3000 个固定种子的差分场景。

这些都是结构或引擎桩验证，不等价于 SC2 客户端实测。游戏内仍需验证面板绘制、跨夜时序与演出。
