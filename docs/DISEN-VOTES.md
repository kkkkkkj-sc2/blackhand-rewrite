# 审计官 disen 后跨日无法提名（shw311）

## 根因

- `gt_removevotes3_Func` 对目标调用强制撤票，再置 `gv_novote=true`，能力仍只持续当天。
- 若目标已经投过提名、审判或跳日票，强制撤票会暂时禁用目标的全部提名按钮，并调用 `gf_ASReEnableButtons(目标, 1.0)`。
- 旧恢复回调虽然接收 `lp_player`，实际却向 `EventPlayer()` 恢复按钮，而不是向参数指定的目标恢复。这依赖原事件上下文，第三方命令无法保证恢复到目标。
- 正常夜间会清除 `gv_novote`，但新一天的投票初始化只恢复可见性和图片，不恢复按钮 Enabled。因此会出现禁投已结束、提名按钮仍被锁住的情况。
- 若目标刚刚提名，其本人上一次投票的一秒恢复回调可能随后解除锁定，解释了报告中的“可能”。先投跳日票没有这个恢复回调，更容易稳定复现。

## 修复

[CustomLogic.galaxy:37773–37796](<work/blackhand/CustomLogic.galaxy#L37773-L37796>) 的恢复回调对三个按钮槽统一使用 `PlayerGroupSingle(lp_player)`，不再读取事件玩家。不改禁投期限、审计官冷却、票权或投票规则。

## 回归和边界

- [新增回归](<tools/test_disen_votes.py>) 抽取真实命令、强制撤票、恢复包装函数/回调以及既有投票处理；以有状态 UI stub 记录 Enabled，并在原生触发器边界排队恢复。夜间只执行实际源文件中的完整资格重置循环，**未模拟完整夜间或 SC2 调度器**。
- 覆盖所有其他玩家槽、事件玩家为审计官或无事件上下文、无旧票/提名票/跳日票/双票/审判票、票权保留、同日依旧禁投、过夜后重新点击提名，以及多个待恢复目标。另将三个按钮槽分别预置为禁用，独立验证恢复目标正确。共 171 组场景，UBSan/bounds 通过。多待恢复目标夹具手动补充审计官充能，不冒充真实双审计官/冷却或异步竞态端到端验证。
- 新测试对修复前源码在目标按钮恢复断言处失败；修复后通过。将三个按钮槽任一行单独改回旧写法，测试均能检出。既有 [主教及投票回归](<tools/test_bishop_votes.py>) 和 Galaxy lint 通过。
- 这些测试不能证明 SC2 中 `TriggerExecute`/`Wait` 后 `EventPlayer()` 的确切值，也不冒充引擎实测。

## 引擎复测步骤

1. A 为审计官，B 为另一存活玩家。
2. B 先投跳日票，A 对 B 使用 `-disen B的楼层号`。
3. 当日 B 仍不能提名、跳日或投审判票。
4. 正常过夜，次日 B 应能点击提名，也应能跳日和投审判票。

旧版特征是次日可能仍不能点击提名，但跳日/审判已能使用。最新修复尚待 SC2 对局核验。
